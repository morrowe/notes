# Урок 6. Кеширование с Redis

Видео: https://itproger.com/course/redis/6

Redis часто используется как кеш: данные, которые часто запрашиваются, временно сохраняются в памяти, чтобы не выполнять тяжелую операцию повторно.

## Что такое кеш

Без кеша:

```text
Пользователь
    ↓
Приложение
    ↓
База данных
    ↓
Результат
```

С кешем:

```text
Пользователь
    ↓
Приложение
    ↓
Redis
 ┌───┴───┐
 HIT     MISS
 ↓        ↓
данные   БД
          ↓
        Redis
```

`HIT` — данные уже есть в кеше.

`MISS` — данных нет, поэтому приложение получает их из основной БД.

## Простой пример

Записать результат:

```redis
SET user:1:name "User" EX 60
```

В течение 60 секунд приложение может брать имя из Redis.

## Почему TTL важен

Кеш не должен бесконечно расти.

Поэтому часто задают срок:

```python
client.set("cache:user:1", "User", ex=60)
```

Через 60 секунд ключ автоматически станет недоступным.

## Пример функции кеширования

```python
import redis

client = redis.Redis(
    host="localhost",
    port=6379,
    decode_responses=True
)

def get_user_name(user_id):
    key = f"cache:user:{user_id}:name"

    cached = client.get(key)

    if cached:
        return cached

    # Здесь вместо примера должна быть настоящая БД
    name = "User"

    client.set(key, name, ex=60)

    return name
```

Логика:

1. Сформировать ключ.
2. Проверить Redis.
3. Если значение найдено — вернуть его.
4. Если нет — получить данные из БД.
5. Положить результат в Redis.
6. Вернуть результат.

## Инвалидация кеша

Если исходные данные изменились, старый кеш может стать неправильным.

Поэтому иногда кеш удаляют:

```python
client.delete("cache:user:1:name")
```

После этого следующий запрос снова получит свежие данные и положит их в кеш.

## Где используют кеш

Например:

- результаты SQL-запросов;
- профили пользователей;
- популярные товары;
- настройки;
- сессии;
- результаты вычислений;
- временные API-ответы.

## Вытеснение данных

Redis может использовать политики eviction, чтобы освобождать память, когда она заканчивается. Один из известных подходов — LRU, то есть удаление давно не использовавшихся данных.

## Практика

Сделать простой кеш:

```python
def get_data():
    cached = client.get("cache:data")

    if cached:
        print("Данные взяты из Redis")
        return cached

    print("Данные получены заново")
    data = "Some expensive result"

    client.set("cache:data", data, ex=30)

    return data
```

Вызвать:

```python
print(get_data())
print(get_data())
```

Первый вызов создаст кеш, второй сможет взять значение из Redis.

## Кратко

Кеширование:

```text
проверить Redis
      ↓
есть? ── да → вернуть
  │
  нет
  ↓
получить из БД
  ↓
записать в Redis
  ↓
вернуть
```
